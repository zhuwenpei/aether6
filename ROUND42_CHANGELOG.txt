AETHER Round 42 — forecast tempo / ensemble speed / dual-cycle selection

1. Forecast-route waypoint tempo
- Strengthened the user-drawn large-scale forecast route tempo mechanism.
- Consecutive close waypoints now produce a clearly visible slowdown/stall in calculateForecastPath.
- Isolated short/long gaps are treated as drawing/omission noise and stay nearly neutral.
- Two or more persistently wide gaps can produce a moderate acceleration without letting one omitted point create a speed spike.
- Legacy forecast minimum-speed floors are scaled by the manual route tempo so they no longer erase an intentional slowdown.

2. Ensemble translation speed hierarchy
- Deterministic/reference forecast remains the first speed baseline, including any slowdown/stall caused by the drawn forecast route.
- Eight model-centre tracks now inherit each 3-hour deterministic displacement, then apply visibly distinct model speed biases.
- Members inherit their parent model-centre displacement, then add persistent/slowly varying member speed biases.
- Tightened baseline step coupling, especially near a route-induced stall, so ensemble geometry cannot run through a deterministic stop.
- Removed duplicate model along-track scale from the geometry-offset term; speed bias is now expressed through the explicit baseline-speed coupling.
- Reduced diagnostic speed smoothing so real model/member timing differences remain visible.

3. Dual-cycle ensemble product
- The dual-cycle product now honors selected model families.
- Removed the old first-50-track truncation that effectively hid later selected models and ignored larger member-count choices.
- All requested members are included in the path population; only node-marker density is adaptively thinned for very large ensembles.
- Side-table rows are sampled round-robin across selected model families.
- Product UI explicitly indicates that model selection and per-model member count apply to both compared cycles.
